# 05. OmniParser 구조 분리와 추가 학습

## 1단계 — 기존 탐지기를 구조 단서로 사용

Microsoft OmniParser V2의 **`icon_detect_v3` 영역 검출기**를 실제 내려받아 실행했다. 사용한 것은 이 검출 단계이지, OCR·아이콘 설명·LLM·자동 DOM 트리 생성 전체가 아니다. 세 고정 부모 창 후보에 사각형을 귀속하고, 훈련 목표 창에서 머리글 아래 반복 탐지되는 여러 자식 영역을 합쳐 마스크를 만들었다. OmniParser와 DINOv3 가중치는 고정했다.

서로 다른 두 확인 시드의 테스트 16세션에서 **첫 11레벨 / 미래 12·16·20레벨** 결과는 다음과 같다. 평가 지표는 목표 부모 창 재탐지다.

| 특징 표현 | 첫 11레벨 | 미래 레벨 | 목표 부재 오탐 |
| --- | ---: | ---: | ---: |
| DINOv3 창 전체 | 0/16 | 0/48 | 0/16 |
| OmniParser 영역 목록만 | 0/16 | 1/48 | 5/16 |
| 가장 큰 자식 하나 제외 + DINO | 3/16 | 13/48 | 0/16 |
| 여러 자식 제외 + DINO | **11/16** | **41/48** | 1/16 |
| 사람이 지정한 내부 마스크 + DINO | 8/16 | 38/48 | 0/16 |

여러 자식 마스크의 첫 변화 11/16 Wilson 95% 구간은 0.44~0.86이다. 수동 마스크 대비 미래 결과 차이의 세션 부트스트랩 95% 구간은 −0.04~+0.19로 우열 확정이 어렵다. 검출기가 변화 전 이펙트와 IoU≥0.5 박스를 낸 것은 16/16이지만 변화 후에는 1/16이었다. 따라서 **마스크 학습에 파서 출력의 품질이 관문**이 됐다.

## 2단계 — 구조 위의 예시/분류기를 게임 피드백으로 갱신

다음 게임 조건에서는 `effect`, `layout`, `layout_mimic`을 두고 클릭의 성공·실패를 확인한 **11레벨 관측 8장**만 온라인 갱신에 사용했다. OmniParser는 여전히 고정이다. `layout` 조건의 마스크된 DINO Exemplar는 미래 12·16·20레벨 **13/24→22/24**, 세션쌍 부트스트랩 개선 +0.38 [0.17, 0.58]이었다. 하지만 목표 부재 화면 오탐이 **4/8**이었다. OmniParser 영역 특징을 입력에 넣은 소형 분류기는 추가 학습 전부터 23/24였고, 8장 갱신 뒤에도 23/24였다. 따라서 이 단계는 **파서 가중치의 지식 증가**를 입증하지 않는다. 오답 클릭이 허용되는 합성 게임에서 8세션의 확인 64건을 얻는 데 성공 64·실패 11, 총 75번 클릭이 필요했다.

## 3단계 — OmniParser 검출 헤드 자체를 추가 학습

게임 피드백으로 같은 창임을 **먼저 확인한** 10·11레벨 쌍을 정렬하고 OpenCV 픽셀 차이로 넓은 ‘변화 영역’ 의사 박스를 만들었다. 공식 `icon_detect_v3`의 마지막 검출 헤드 12개 텐서에 역전파를 적용했다. 1·3·8장 예산별로 원본에서 따로 시작해 각각 100단계를 학습했다. 미래 12·16·20레벨의 **최고점 변화 박스** IoU≥0.5는 보류 6세션에서 **0/18→18/18**이었다. 그러나 옛 10레벨은 1장 학습 직후 **6/6→4/6**으로 떨어져 순위 망각이 보였다.

더 중요한 구분은 **경계 품질과 부모 정체성이 다르다**는 점이다. 한 장의 10레벨 참조만 이용한 세 후보 중 같은 창 선택은 가림 없음 3/18, 고정 마스크 4/18, 학습 OmniParser 마스크 최대 4/18이었다. 박스를 18/18 맞힌다고 11레벨 이후 창을 잘 재식별하는 것은 아니었다. 이 학습은 이펙트·레벨·진행 막대를 각각 의미적으로 분할한 것도 아니다.

## 결론

OmniParser는 ‘학습 불가’가 아니다. **일부 검출 헤드의 경계 학습은 실제로 성공**했다. 다만 첫 11레벨은 게임 확인이 먼저 필요하고, 세 고정 창·같은 렌더러 밖의 일반화, 부모-자식 의미 구조, 부재 거절, 이전 상태 보존까지 해결한 것은 아니다.
