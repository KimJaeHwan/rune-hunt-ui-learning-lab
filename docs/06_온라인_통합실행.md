# 06. 실제 게임 피드백을 묶은 온라인 통합 실행

## 첫 연결 — 부모 창 찾기 → 정체 선택 → 게임 확인 → 갱신

전체 화면을 받은 YOLO가 부모 창 상자를 제안하고, OmniParser가 자식 상자를 제안하며, 고정 DINOv3 특징의 원본·마스크 버전을 Exemplar/작은 선형 분류기로 비교했다. 예측한 창을 눌러 받은 **게임 행동 영수증**만 온라인 학습에 넣었다. 화면 ID와 행동 ID를 연결해 중복·오래된 피드백을 거르는 검사를 넣었다. 평가 정답은 모델 입력과 분리했다.

초기 분류기는 훈련 12프레임의 부모 crop 36개(양성 10, 음성 26)로 시작했다. 적응 4세션에서 확인 28건(양성 24, 음성 4)을 얻었다. **YOLO와 OmniParser 가중치는 이 첫 연결 시험에서 고정**됐고, Exemplar 기억과 작은 목표 분류기만 갱신했다. 미래 12세션에서 후보 모델의 목표 정답은 **38/72→62/72**였으나, 부재 오탐은 **10/12→12/12**로 악화됐다. 검증 게이트가 이를 거부해 실제 채택 정책은 기본 모델을 유지했다. 후보 모델이 12세션 모두 여섯 단계에 도달했다는 관측도 있지만, 없는 창을 클릭하려는 오류 때문에 안전한 성공으로 볼 수 없다. 사라진 창에서 멈추는 능력이 필요한 이유가 여기 있다.

## 세 학습기를 모두 갱신하는 후속 실행

다음 실행은 **YOLO11n 부모 검출기**, **DINOv3 특징 메모리·선형 목표 분류기**, **OmniParser V2 검출 헤드**를 같은 확인 기록으로 추가 학습했다. 초기 YOLO는 이미 48라벨 화면으로 학습됐고, 목표 분류기는 위 12프레임/36 crop에서 출발했다. 네 적응 세션의 확인 기록은 10+6+6+6=28건이었다. 동일한 미래 네 세션을 매 체크포인트에 반복해서 봤다.

| 누적 확인 | YOLO 부모 재탐지 | 목표 창 선택 | OmniParser 선택 변화 박스 IoU≥0.5 | 부재 오탐 | YOLO 별도 검증 mAP50–95 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 0 | 24/24 | 12/24 | 0/4 | 3/4 | 0.813 |
| 10 | 24/24 | 18/24 | 0/4 | 4/4 | 0.828 |
| 16 | 24/24 | 21/24 | 0/4 | 4/4 | 0.865 |
| 22 | 24/24 | 22/24 | 0/4 | 4/4 | 0.891 |
| 28 | 24/24 | 21/24 | 0/4 | 4/4 | 0.919 |

**동시에 학습은 했다. 동시에 좋아진 것은 아니다.** 부모 재탐지는 시작부터 포화였고, 정체 선택은 올랐다가 마지막에 떨어졌다. OmniParser 손실이 감소해도 실제 최고점 변화 박스는 0/4였다. 부재 오탐 4/4는 자동 행동을 막는 실패 조건이다. 첫 실패 실행에서는 확인 창 하나만으로 YOLO를 갱신해 부모 재탐지가 24/24→0/24로 붕괴했다. 수정 실행에서는 낮은 학습률, 다른 창의 고신뢰 의사 라벨 보존, 검증 게이트를 넣어 붕괴를 막았지만 **의사 라벨 오염** 위험은 남는다.

## 시스템적 해석

원하는 루프는 `발견 → 정체 후보 → 시간·행동 확인 → 확인된 데이터만 갱신 → 이전 상태·부재 검증 → 채택/보류`다. 이번 연결은 이 흐름의 상당 부분을 실행했지만, 독립 게임에 배포 가능한 완성판은 아니다. 특히 ‘창이 없어졌음’을 행동 정지 조건으로 삼아야 잘못된 지식을 누적하지 않는다. 4개 미래 세션을 반복 평가했고 실패 뒤 설정을 수정했으므로 위 표를 독립 최종 성능이나 통계적 유의성으로 읽으면 안 된다.

실행 근거: 원본 `integrated_trial.py`, `integrated-data/integrated-trial-report.json`, `joint_online_trial.py`, `joint-online-report.md`, `joint-online-data/live-three-learners-safe/report.json`.
