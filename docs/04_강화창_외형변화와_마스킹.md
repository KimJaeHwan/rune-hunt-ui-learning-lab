# 04. 강화 창 외형 변화와 마스킹

## 문제가 생긴 순간

특성 강화 창을 1~10레벨의 외형으로 배웠다가 11레벨에서 내부 이펙트·레벨 숫자·진행 영역이 화려하게 바뀌면, **창 자체는 같아도 전체 이미지 특징은 달라진다**. 부모 창의 정체와 내부 상태를 한 벡터로 묶은 것이 실패의 한 원인이었다. 화면에 같은 크기의 창 세 개가 있다는 사전 조건 아래서 이 문제를 재현했다.

## 첫 특징 비교

훈련 8·검증 4·테스트 8세션에서 변화 전후를 비교했다. DINOv2/v3의 전체 crop, 외곽 프레임 패치, 내부 패치를 나눠 쓰고, 수동으로 예상 변화 영역을 가리는 대조군도 만들었다. 대표 실행에서 **전체 DINOv3+Exemplar 첫 11레벨 0/8**, 내부를 알고 가린 특징과 Adapter 조건은 **8/8**이었다. 다른 설정·시드의 결과와 혼동하면 안 되므로 이 값을 범용 성능으로 쓰지 않는다. 외곽만 보게 하는 방식은 이 게임에서는 도움이 됐지만, 어떤 영역을 가려야 할지 미리 안다는 전제가 문제였다.

## 변화가 난 뒤 OpenCV 차이를 쓰면?

같은 부모 창의 10·11레벨 화면을 정렬해 픽셀 차이를 보면 바뀐 영역을 찾을 수 있다. 그러나 **첫 11레벨 창을 이미 같은 부모로 확인**해야 전후 차이를 계산할 수 있다. 첫 재탐지 실패를 OpenCV가 혼자 역으로 해결하는 구조는 아니다. 또 이미지 특징이나 Adapter 가중치의 ‘내부 영역만 지우기’는 일반적인 신경망 가중치에서 국소적으로 보장되지 않는다. 구현한 방향은 원본 상태의 예시를 보존하고, 마스크된 특징을 다시 추출하거나 확인된 새 상태를 별도 메모리에 추가하는 것이었다.

## 다음 단계로 넘어간 이유

사람이 변화할 부분을 선지정하지 않으려면 부모 창 안을 **요소별 후보**로 나눠야 한다. 이때 도입한 것이 OmniParser의 영역 탐지와, 나중의 OpenCV/DINO 특징 맵 기반 계층 탐색이다. 다만 ‘상자를 나누었다’와 ‘어느 요소가 안정/변화/정체성 핵심인지 안다’는 다르다.

실행 근거: 원본 `UPGRADE_EXPERIMENT.md`, `upgrade_benchmark.py`, `upgrade.js`, `upgrade-dataset.json`, `omniparser_incremental_eval.py`. 수동 마스크의 숫자는 특정 실험 조건의 관측 예시다.
